# متطلبات المنتج — منصة أسر المنطقة

## 1. الرؤية

إنشاء منصة رقمية موثوقة لمنطقة جغرافية واحدة تضم عدة أسر وعائلات، هدفها توثيق الأشخاص والأنساب والصلات الاجتماعية والمناسبات والتاريخ المحلي، مع المحافظة على استقلال كل أسرة وخصوصية أفرادها.

المنصة ليست شبكة اجتماعية مفتوحة للنشر المباشر، وليست شجرة لعائلة واحدة. هي سجل مجتمعي يخضع للمراجعة والاعتماد.

## 2. المبادئ الأساسية

1. المنطقة تضم عدة أسر قد ترتبط أو لا ترتبط ببعضها.
2. لكل شخص سجل موحد واحد فقط.
3. حساب المستخدم منفصل عن سجل الشخص.
4. كل عائلة كيان مستقل، والزواج يربط عائلتين دون دمجهما.
5. تخزن العلاقات الأساسية الموثقة، وتستنتج القرابات المركبة آليًا.
6. لا يظهر محتوى المستخدمين للعامة قبل الاعتماد.
7. الخصوصية الافتراضية محافظة، خصوصًا للأحياء والأطفال.
8. عند غياب مسار قرابة، تكون الرسالة: «لا توجد علاقة مسجلة في البيانات الحالية».

## 3. الكيانات الرئيسية

### المنطقة

تمثل النطاق الجغرافي للمنصة. يصمم النظام لدعم أكثر من منطقة مستقبلًا، مع تشغيله مبدئيًا لمنطقة واحدة.

### العائلة

بياناتها:

- الاسم العربي والإنجليزي.
- الأسماء البديلة وأسماء الشهرة.
- الأصل والمناطق المرتبطة.
- نبذة تاريخية.
- الشعار أو الصورة.
- مستوى الخصوصية.
- مسؤول أو أكثر.
- حالة الاعتماد.

### فرع العائلة

قد يمثل فرعًا أو بيتًا أو فخذًا، ويمكن أن يتفرع من فرع آخر.

### الشخص

بياناته المحتملة:

- الاسم الكامل وأجزاؤه.
- الأسماء البديلة واسم الشهرة.
- الجنس.
- الميلاد والوفاة بصورة كاملة أو تقريبية.
- الحالة: حي أو متوفى.
- المدينة ومكان الأصل.
- السيرة والمهنة والإنجازات.
- الصورة.
- مستويات ظهور الحقول.
- حالة الاعتماد.

### الارتباط بالعائلة

يسمح بربط الشخص بأكثر من عائلة دون تكراره، مثل:

- العائلة الأساسية.
- عائلة الأب.
- عائلة الأم.
- ارتباط عن طريق الزواج.
- ارتباط اجتماعي أو تاريخي.

### علاقات الوالدين

تخزن علاقة الأب أو الأم بالابن أو الابنة، مع درجة التوثيق والمصدر وحالة الاعتماد.

### الزواج

كيان مستقل يحتوي على الطرفين، التاريخ التقريبي أو الكامل، الحالة الحالية، تاريخ الانتهاء وسببه عند الحاجة، والخصوصية.

## 4. الأدوار

### الزائر

- البحث في المحتوى العام.
- عرض الأشخاص والعائلات والأحداث المعتمدة.
- لا يستطيع الإضافة أو التعديل أو رفع الملفات.

### المستخدم المسجل

- تقديم طلب إضافة شخص أو عائلة أو فرع أو علاقة.
- تقديم تصحيح أو خبر أو مناسبة أو ملف.
- متابعة طلباته وتعليقات المراجعة.
- لا ينشر مباشرة.

### عضو موثق من المنطقة

- حسابه مرتبط بسجل شخص معتمد.
- يستطيع معرفة علاقته الشخصية بالأشخاص والمناسبات بحسب الخصوصية.
- يمكنه رؤية المحتوى الخاص بأعضاء المنطقة الموثقين.

### مسؤول فرع أو عائلة

- يراجع طلبات النطاق المكلف به.
- لا يستطيع اعتماد طلبه الشخصي.
- لا يرى البيانات الخاصة لعائلات غير مكلف بها.

### مشرف المحتوى

- يدير الأخبار والمناسبات العامة وفق الصلاحيات.

### مدير النظام

- يدير الأشخاص والعائلات والعلاقات والمستخدمين والمراجعات والتقارير.

### المدير الأعلى

- يدير الصلاحيات الحساسة والحذف النهائي والتصدير والإعدادات الأمنية.

## 5. البحث

يجب دعم البحث عن:

- شخص.
- عائلة.
- فرع.
- مناسبة.
- خبر.
- متوفى.
- شخصية تاريخية.

يدعم البحث العربي:

- إزالة التشكيل.
- توحيد أشكال الألف والهمزة.
- معالجة الياء والألف المقصورة.
- الأسماء البديلة.
- الاسم المشهور.
- البحث الجزئي.

نتيجة الشخص تعرض ما يكفي للتفريق بين المتشابهين دون كشف بيانات خاصة، مثل العائلة واسم الأب وسنة الميلاد التقريبية والمدينة.

## 6. الشجرة والعلاقات

### عرض الشجرة

- الأسرة المباشرة.
- الأصول فقط.
- الفروع والأبناء فقط.
- عدد محدد من الأجيال.
- تكبير وتصغير وتحريك.
- فتح ملف الشخص من العقدة.
- تمييز المتوفى.
- تمييز العلاقات غير المكتملة أو المستنتجة.
- بديل نصي قابل للوصول لذوي الاحتياجات.

### البحث عن العلاقة

يختار المستخدم شخصين، وتعرض المنصة:

- العلاقة المختصرة.
- المسار بينهما خطوة بخطوة.
- الجد المشترك عند وجوده.
- المسارات البديلة عند تعددها.
- علاقة المصاهرة بصورة صريحة.

### القيود

- منع الشخص من أن يكون والدًا لنفسه.
- منع العلاقة المكررة.
- كشف الدورات غير المنطقية.
- تحذير من فروق الأعمار والتواريخ غير المنطقية.
- عدم حذف التاريخ السابق للزواج عند انتهاء العلاقة.

## 7. المناسبات

الأنواع الأساسية:

- وفاة وعزاء.
- زواج.
- عقد قران.
- خطوبة.
- مولود.
- سماية.
- نجاح وتخرج.
- ترقية أو تكريم.
- مرض أو زيارة.
- اجتماع أو فعالية عامة للمنطقة.
- خبر أو إعلان اجتماعي.

بيانات المناسبة:

- النوع والعنوان والوصف.
- الأشخاص والعائلات المرتبطة وأدوارهم.
- التاريخ والوقت.
- الموقع والعنوان ورابط الخريطة.
- صور وبطاقات.
- جهة التواصل المسموح بنشرها.
- مستوى الظهور.
- تاريخ انتهاء العرض.
- حالة الاعتماد والإلغاء.

### الوفاة والعزاء

قد تشمل:

- المتوفى.
- تاريخ الوفاة.
- الصلاة والدفن.
- مكان ووقت عزاء الرجال والنساء.
- أقارب المتوفى المعتمدون لاستقبال التعازي.
- نص النعي.

### الزواج

قد تشمل:

- العريس والعروس.
- العائلتان.
- والدا الطرفين.
- المكان والتاريخ والوقت.
- بطاقة الدعوة وتعليمات الحضور.

### العلاقة بالمناسبة

للعضو الموثق تعرض المنصة:

- علاقته بالشخص الرئيسي.
- علاقته بأقرب الأقارب المرتبطين بالمناسبة.
- من يناسب التواصل معه للتعزية أو التهنئة.

## 8. الأخبار والذاكرة المحلية

- أخبار عامة للمنطقة.
- أخبار عائلية.
- شخصيات وسير.
- صور وذكريات تاريخية.
- نجاحات وإنجازات.
- ربط الخبر بالأشخاص والعائلات.
- مصادر ومراجع عند الحاجة.
- اعتماد إداري قبل النشر.

## 9. دورة الاعتماد

الحالات:

1. مسودة.
2. مقدم.
3. بانتظار المراجعة.
4. تحت المراجعة.
5. يحتاج معلومات إضافية.
6. محول لمسؤول العائلة أو الإدارة.
7. معتمد.
8. معتمد جزئيًا.
9. مرفوض.
10. ملغي.
11. مؤرشف.

شاشة المراجعة تعرض:

- مقدم الطلب.
- البيانات الحالية والمقترحة.
- الفروق.
- التعارضات والتكرار المحتمل.
- الملفات والمصادر.
- الأثر المتوقع على الشجرة.
- سجل التعليقات والقرارات.

## 10. اكتشاف التكرار والدمج

تستخدم مؤشرات مثل:

- الاسم وأسماؤه البديلة.
- الأب والأم.
- سنة الميلاد.
- الزوج أو الزوجة.
- العائلة والفرع.
- المدينة.

الدمج الإداري يجب أن:

- ينقل العلاقات والأحداث والوسائط.
- يحافظ على سجل العملية.
- يسمح بالمراجعة قبل الحذف النهائي.
- يمنع فقد الروابط الخارجية.

## 11. لوحة التحكم

### مؤشرات عامة

- عدد العائلات والفروع والأشخاص.
- الأحياء والمتوفون.
- العلاقات والزيجات.
- المستخدمون والأعضاء الموثقون.
- المناسبات والأخبار.
- الطلبات المعلقة.

### التحليلات

- الزيارات اليومية والفريدة.
- أكثر الصفحات والأشخاص والعائلات مشاهدة.
- عمليات البحث وعمليات البحث دون نتائج.
- أنواع الأجهزة ومصادر الزيارة بصورة تحترم الخصوصية.

### جودة البيانات

- أشخاص دون عائلة أساسية.
- أشخاص دون والدين مسجلين.
- سجلات مكررة محتملة.
- علاقات متعارضة.
- عائلات بلا مسؤول.
- طلبات متأخرة.
- أحداث منتهية لا تزال ظاهرة كقادمة.

## 12. الإشعارات

- استلام الطلب.
- بدء المراجعة.
- طلب معلومات.
- قبول أو رفض.
- مناسبة مرتبطة بقريب.
- وفاة أو مناسبة في العائلة أو الفرع وفق تفضيلات المستخدم.

يدعم النظام مبدئيًا إشعارات داخل المنصة، ثم البريد أو إشعارات المتصفح أو خدمات خارجية مستقبلًا.

## 13. الخصوصية

مستويات الظهور المقترحة:

- عام.
- مستخدمون مسجلون.
- أعضاء المنطقة الموثقون.
- عائلات محددة.
- فروع محددة.
- المشرفون.
- خاص.

لا يظهر للعامة افتراضيًا:

- رقم الهوية.
- الهاتف والبريد الخاصان.
- العنوان المنزلي.
- الموقع الدقيق.
- المعلومات الصحية.
- المستندات.
- تاريخ الميلاد الكامل للأحياء.
- معلومات الأطفال الحساسة.

## 14. متطلبات النسخة الأولى

تعتبر النسخة الأولى جاهزة عندما:

1. يعمل التسجيل والدخول وربط الحساب بالشخص عبر اعتماد.
2. يمكن إدارة المنطقة والعائلات والفروع والأشخاص.
3. يمكن تسجيل الوالدين والزواج.
4. يعمل البحث العربي.
5. تعمل صفحات الشخص والعائلة والشجرة الأساسية.
6. يمكن تقديم ومراجعة واعتماد الطلبات.
7. تعمل الوفيات والزيجات والسمايات والأخبار.
8. لا يظهر المحتوى غير المعتمد للعامة.
9. تطبق سياسات RLS فعليًا.
10. تعمل لوحة التحكم والسجل الإداري الأساسي.
11. تعمل المنصة على الجوال والكمبيوتر وRTL وLTR.
12. يتم البناء والنشر تلقائيًا من GitHub.
