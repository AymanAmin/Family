# المدير الأعلى الرئيسي

تم اعتماد حساب واحد بصفة **المدير الأعلى الرئيسي** للمنصة.

## التنفيذ الأمني

- هوية الحساب محفوظة داخل migration كبصمة SHA-256، وليس كبريد واضح داخل المستودع العام.
- الملف المسؤول: `supabase/migrations/202608070002_bootstrap_primary_super_admin.sql`.
- يمنح الحساب:
  - `role = super_admin`
  - `is_primary_admin = true`
  - `account_status = active`
- تحفظ المطالبة الموثوقة أيضًا في `auth.users.raw_app_meta_data` ولا تؤخذ الصلاحيات من `user_metadata` القابلة للتعديل.
- يسمح النظام بوجود مديرين آخرين مستقبلًا، لكن يفرض وجود مدير رئيسي واحد فقط بواسطة unique index.
- إذا كان الحساب موجودًا قبل تنفيذ migration فسيتم ترقيته فورًا.
- إذا لم يكن موجودًا، فسيحصل على الصلاحية تلقائيًا عند التسجيل أو أول تحديث لحسابه.
- تغيير البريد المعتمد عن الحساب يزيل صفة المدير الرئيسي منه تلقائيًا.

## قاعدة إلزامية

لا يجوز منح صلاحية المدير الأعلى من كود الواجهة، أو اعتمادًا على مقارنة البريد داخل React، أو من بيانات `user_metadata`. التحقق يجب أن يعتمد على الدور المحمي في قاعدة البيانات وسياسات RLS أو `app_metadata` الموثوقة.

## حالة التطبيق

وجود migration داخل GitHub لا ينفذها تلقائيًا على قاعدة Supabase ما لم يتم تشغيل migrations على مشروع Family. عند تجهيز مسار نشر قاعدة البيانات من GitHub يجب أن تشمل هذه migration ضمن `supabase db push`.
